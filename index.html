01 / PET PROJECT

What I build on my own time

FEATURED · OPEN SOURCE Playwright · TypeScript · Claude Code agents · GitHub Actions

aqa-shop-agentic-qa: AI agents write the tests, guardrails make them trustworthy

AI writes tests fast, but a green test written by AI proves nothing on its own. In this project, a team of Claude Code agents turns manual test cases into Playwright tests for a demo online shop, and scripts and git hooks check that every result is honest.

  1. INPUTManual test caseRead-only for AI
  2. AGENTPlannerExplores the live app
  3. AGENTGeneratorSpec + Page Objects
  4. AGENTHealerFixes tests, not bugs
  5. SCRIPTMutation checkEvery assertion must fail
  6. AGENTReviewerCoverage vs test case
  7. HUMANMe + CIApprove plan and PR

An orchestrator with human stops

One agent routes each test case through every stage and stops twice for my approval: after the plan and before the PR.

No faking a green run

Agents can’t weaken assertions, add retries or skips. A real product bug becomes a bug report draft instead.

Proof that tests can fail

A mutation check breaks expected values one by one. If the suite stays green, the check fails.

Quality gates everywhere

Lint and typecheck on every file an agent writes, a review gate before push, CI on every PR and a nightly run.

CASE-01 · WEB Playwright · TypeScript · Azure DevOps

Web test automation, built from zero

CONTEXT

A ticketing platform for tourist attractions with no automated tests. Two QA engineers spent two days on manual regression every release.

WHAT I DID

Chose the stack and designed the framework. Automated the admin web and ticket sales through the kiosk and box office. Built the full purchase flow, from picking a ticket to receiving it by email, with my own test inbox service. Connected it all to CI on every staging deploy.

RESULT

About half of the manual regression is now done by automated tests in CI, so manual time goes to new features.

CASE-02 · MOBILE Appium · Robot Framework · Java

Mobile automation from scratch

An e-learning app for iOS and Android with releases every two weeks and only manual testing. On my own, I evaluated the tools, built the mobile framework and automated the whole user flow: login, joining a virtual class, audio and video, and in-class activities.

Every bi-weekly release got checked against the full student journey on both platforms.

CASE-03 · LOAD k6 · API · Dev collaboration

Load testing together with developers

The payment flow had no step-by-step documentation, and two production issues were caused by load. I mapped the flow from network traffic, wrote k6 load scripts and worked with developers on scenarios, results and fixes.

Both fixes confirmed under load, and a new backend bug found along the way.

CASE-04 · INCIDENT k6 · AI-assisted scripting

Checking the fixes after a DDoS attack

Our production site was hit by a DDoS attack, and I was asked to verify the fixes. I got up to speed with k6 quickly and, with AI help, wrote scripts that reproduce attack-like traffic: bursts of repeated requests to key pages and the payment flow, to see whether rate limiting holds.

The fixes were checked with repeatable tests instead of waiting for the next attack.

03 / APPROACH

Common QA problems and how I solve them

PROBLEM

Regression eats the release

I automate the business-critical paths first and run them in CI on every build, so manual time goes to what’s new.

PROBLEM

Bugs bounce between teams

Before filing, I find the cause through network traffic, logs and error tracking, so the right developer gets a report they can act on.

PROBLEM

“Works on my machine”

I check time zones, browsers and real iOS and Android devices, because many bugs only show up in one environment.

PROBLEM

Integrations fail unpredictably

Payments, printers and third-party scripts get tested on their bad days too: timeouts, server errors and rate limits.

PROBLEM

Business rules are unclear

I turn them into ordered rules and decision tables, agree them with the team, then test against them.

PROBLEM

Code ships faster than tests

AI helps me prepare checklists, test cases and reports quickly. I review everything, because AI gets business logic wrong too.
